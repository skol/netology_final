## 🏗️ Архитектура

Проект построен вокруг **гибридного ансамбля**: каждому пользователю назначается
модель, наиболее подходящая для его категории.

| Категория | Размер истории   | Модель | Обоснование |
|-----------|------------------|--------|-------------|
| 🧊 Cold | ≤ 238 действий   | **FPMC** | Марковские переходы работают даже на короткой истории |
| 🔥 Warm | 238–368 действий | **SASRec** | Transformer улавливает последовательные паттерны |
| 🔥🔥 Hot | > 368 действий   | **LightGCN** | Графовая агрегация раскрывается на богатой истории |

Категория определяется размером истории пользователя в тренировочном периоде (все взаимодействия: позитивные + негативные).

## 🧠 Реализованные модели

### 1. Most Popular (baseline)
Ранжирует айтемы по частоте позитивных взаимодействий в трейне. Рекомендует топ-K, которые пользователь ещё не видел.

### 2. FPMC — Factorized Personalized Markov Chains
> Rendle et al., *FPMC: Factorizing Personalized Markov Chains for Next-Basket Recommendation* (WWW 2010)

$$\text{score}(u, l, i) = \langle U_u, V_i \rangle + \sum_d BU_{u,d} \cdot T_{l,d} \cdot T_{i,d}$$

CP-декомпозиция тензора переходов «пользователь × последний × следующий».
MF-часть ловит вкус пользователя, MC-часть — персонализированные переходы между айтемами.

### 3. LightGCN — Light Graph Convolution Network
> He et al., *LightGCN: Simplifying and Powering Graph Convolution Network for Recommendation* (SIGIR 2020)

$$E^{(k+1)} = \tilde{A} E^{(k)}, \quad \tilde{A} = D^{-1/2} A D^{-1/2}$$
$$e = \frac{1}{K+1} \sum_{k=0}^{K} e^{(k)}$$

Никаких нелинейностей и весов на рёбрах — только линейная агрегация соседей
и усреднение эмбеддингов по всем слоям. Обучается через BPR-loss.

### 4. SASRec — Self-Attentive Sequential Recommendation
> Kang & McAuley, *Self-Attentive Sequential Recommendation* (ICDM 2018)

Transformer-энкодер с **causal mask** (не подглядывает в будущее) и **padding mask**
(игнорирует нулевые позиции). Предсказывает следующий айтем по последовательности.

## 📊 Метрики и оценка

Все модели оцениваются на валидационной неделе (в конфиге тренировки) по трём метрикам:
- **Recall@K** — доля верных айтемов в топ-K
- **NDCG@K** — нормализованный дисконтированный кумулятивный выигрыш
- **MRR@K** — средний обратный ранг первого верного айтема

**Ключевое правило:** при подсчёте метрик из кандидатов **исключаются все айтемы**,
с которыми пользователь взаимодействовал в трейне (и позитивные, и негативные).
Это предотвращает завышение метрик за счёт «угадывания» уже увиденного.

Результаты сохраняются в `train/results/metrics_by_group.csv` — таблица `(group, model, n_users, recall@K, ndcg@K, mrr@K)`.

## 🚀 Как запустить

### Локально
```bash
pip install -r requirements.txt
# PyTorch с CUDA (или CPU-версия)
pip install torch --index-url https://download.pytorch.org/whl/cu124

# Обучение всех моделей
python -m train.run_training --models most_popular,fpmc,light_gcn,sasrec

# Метрики по группам
python -m train.evaluate_groups

# Инференс для конкретного пользователя
python -m train.inference --user-id 12345 --k 10
```

### Через Docker

```bash
docker-compose up --build
```

Конфиг выбирается переменной окружения TRAIN_CONFIG:
- train.config — локальный запуск (быстрые дефолты)
- train.config_docker — GPU-инфраструктура

# ⚠️ Методологические заметки
- **Разметка позитив/негатив.** Позитив = timespent ≥ 5с ИЛИ одна из реакций
    (like, share, bookmark, click_on_author, open_comments).
    Негатив = не позитив И (timespent < 5с ИЛИ dislike).
    Правило «позитив побеждает»: при наличии любого позитивного сигнала
    действие считается позитивным, даже если стоит dislike.
    Null в полях реакций трактуется как False, null в timespent — как 0.
- **Negative sampling (BPR).** Негативный айтем семплируется из явных негативов
    пользователя (skip/dislike), если они есть; иначе — равномерно из всех айтемов.
    **Критично:** из кандидатов исключаются **все позитивные айтемы пользователя**,
    а не только текущий pos_item. Это предотвращает обучение на «негативах»,
    которые на самом деле являются позитивными.
- **Хронологический порядок.** В VK-LSVD нет колонки времени — порядок
    взаимодействий задаётся порядком строк в parquet. Перед группировкой по
    user_id данные явно сортируются по глобальному индексу строки.
