# MostPopular (Non-personalized Popularity Baseline)
**Идея.** Предсказывать следующий item как наиболее частый в обучающей выборке, исключая уже просмотренные пользователем.

**Формализация.** Для каждого $item\ i$ считаем частоту в train:

$$\text{score}(i) = \sum_{u} \sum_{t} \mathbb{I}(i_{u,t} = i)$$

где $i_{u,t}$ — item, взаимодействованный пользователем $u$ в момент $t$.

**Прогноз.** Для пользователя $u$ с историей $H_{u}$: $$top\text{-}K(u)=argtop\text{-}K_{i\notin{H_{u}}}score(i)$$

**Что проверяет.** Нижний baseline: «а не хуже ли мы простой глобальной популярности?»

**Вариант.** Recent MostPopular — то же самое, но с time-decay или по скользящему окну:
$$score_{recent}(i)=\sum_{u,t;t \geq T_{cutoff}}\mathbb{I}(i_{u,t}=i)$$

# FPMC (Factorized Personalized Markov Chains)
**Идея.** Комбинировать персональные предпочтения (матричная факторизация) и переходы между соседними items (марковская цепь первого порядка).

**Модель.** Вероятность перехода от $item\ i$ к $item\ j$ для пользователя $u$:
$$P(j \mid u, i) \propto \underbrace{\mathbf{p}_u^\top \mathbf{q}_j}_{\text{MF: общие предпочтения}} + \underbrace{\mathbf{r}_i^\top \mathbf{s}_j}_{\text{MC: переход } i \to j}$$

где:
- $p_{u},q_{j} \in \mathbb{R}^d$ — эмбеддинги пользователя и item для MF-компоненты.
- $r_{i},s_{j} \in \mathbb{R}^d$ — эмбеддинги item как источника и цели перехода для MC-компоненты.

**Обучение.** Pairwise ranking loss с negative sampling (BPR-style):
$$\mathcal{L} = -\sum_{(u,i,j) \in \mathcal{D}} \ln \sigma \left( \hat{y}_{u,i,j^+} - \hat{y}_{u,i,j^-} \right) + \lambda \|\Theta\|^2$$

где $\hat{y}_{u,i,j}=p_{u} \top q_{j}+r_{i} \top s_{j}$, $j^+$ — реальный следующий item, $j^-$ — негативный сэмпл.

**Что проверяет.** Достаточно ли для good next-item prediction комбинации «общий вкус + последний просмотр», без длинной истории.

**Особенности.**
- Требует хотя бы один предыдущий item для контекста.
- Для пользователей с одним interaction — fallback на MostPopular.

# SASRec (Self-Attentive Sequential Recommendation)
**Идея.** Использовать **self-attention** для кодирования упорядоченной истории пользователя и предсказания следующего item 
на основе всего контекста, а не только последнего.

**Вход.** Последовательность $items$ для пользователя $u$: $$\mathbf{S_{u}}=[i_{1},i_{2},...,i_{t}]$$ 
каждый $item$ маппится в эмбеддинг $\mathbf{e_{i_{k}}} \in \mathbb{R}^d$.

**Позиционное кодирование.** Добавляется к item эмбеддингам: $$\mathbf{h_{k}}=\mathbf{e_{i_{k}}}+\mathbf{pos_{k}}$$

**Self-Attention.** Multi-head attention с causal mask (будущее скрыто):
$$Attention(\mathbf{Q,K,V})=softmax(\frac{\mathbf{QK}^T}{\sqrt{d}})\mathbf{V}$$

где $Q=K=V=[h_{1},...,h_{t}]$, и $mask$ запрещает внимание к позициям $>k$ для позиции $k$.

**Выход.** 
Финальный эмбеддинг последовательности — обычно последний hidden state после нескольких слоёв attention + feed-forward:
$$\mathbf{z_{u}}=SASRec(\mathbf{S_{u}})[-1] \in \mathbb{R}^d$$
 
**Прогноз.** Score для кандидата $item j$: $$\hat{y}_{u,j}=\mathbf{z_{u}e_{j}}$$

**Обучение.** Cross-entropy или pairwise loss на next-item prediction:
$$\mathcal{L}=-\sum_{u}\sum_{t}\ln P(i_{t+1}|i_{1},...,i_{t})$$
или BPR-style pairwise loss аналогично FPMC.

**Что проверяет.** Полезен ли длинный контекст последовательности (больше одного предыдущего item) для предсказания следующего.

**Особенности.**
- Требует causal mask, чтобы не заглядывать в будущее.
- Обычно обрезают историю до max_seq_len и делают padding.
- Минимальная длина последовательности — 2 (хотя бы один context + target).

# LightGCN (Light Graph Convolutional Networks for Recommendation)
**Идея.** Строить user-item двудольный граф (bipartite graph) и обучать эмбеддинги через упрощённую graph convolution, 
оставляя только neighborhood aggregation (без нелинейностей и learnable weight матриц).

**Граф.** Bipartite graph $\mathcal{G}=(\mathcal{U} \cup \mathcal{I,E})$, где $(u,i) \in \mathcal{E}$ если пользователь
$u$ взаимодействовал с $item\ i$ в train.

**Propagation rule.** На слое $k$:
$$e_{u}^{(k+1)}=\sum _{i\in \mathcal{N}_{u}}\frac{1}{\sqrt{|{}\mathcal{N}_{u}|{}\cdot |{}\mathcal{N}_{i}|{}}}e_{i}^{(k)}$$
$$e_{i}^{(k+1)}=\sum _{u\in \mathcal{N}_{i}}\frac{1}{\sqrt{|{}\mathcal{N}_{i}|{}\cdot |{}\mathcal{N}_{u}|{}}}e_{u}^{(k)}$$
где $\mathcal{N}(u)$ — соседи пользователя (items), $\mathcal{N}(i)$ — соседи item (users).

**Финальный эмбеддинг.** Конкатенация или сумма по всем слоям:
$$e_{u}^*=\sum _{k=0}^{K}\alpha _{k}e_{u}^{(k)}$$
$$e_{i}^*=\sum _{k=0}^{K}\alpha _{k}e_{i}^{(k)}$$
Обычно веса фиксируются как $\alpha_k = \frac{1}{K+1}$, что эквивалентно простому усреднению.
 
**Прогноз.** Score для пары $(u, i)$: $$\hat{y}_{u,i}=e_{u}^* \top e_{i}^*$$

**Обучение.** BPR pairwise loss: 
$$\mathcal{L}=-\sum_{(u,i^+,i^-)\in\mathcal{D}}\ln \sigma(\hat{y}_{u,i^+}-\hat{y}_{u,i^-})+\lambda\lVert\Theta\rVert^2$$
где $i^+$ — позитивный (было взаимодействие), а $i^-$ — негативный сэмпл.

**Что проверяет.** Полезен ли collaborative signal из графа взаимодействий без учёта порядка и времени.

**Особенности.**
- Не sequential: порядок взаимодействий игнорируется.
- Обычно оценивается в full-ranking среди всех неинтерактированных items.
- Для next-item evaluation можно использовать тот же scoring, но интерпретация меняется.

# Сегментация пользователей

Для анализа качества моделей пользователи разбиваются на три группы по длине истории в обучающем окне:
$$
segment(u)=\left\{ 
\begin{aligned}
cold,\ |\mathbf{S_{u}}|\leq 30 \\ 
warm,\ 30 \leq |\mathbf{S_{u}}| \leq 70 \\
hot,||\mathbf{S_{u}}| \gt 70
\end{aligned} 
\right.
$$

Метрики $(Recall@K, NDCG@K, MRR@K)$ вычисляются отдельно для каждого сегмента, что позволяет выявить, 
какая модель эффективнее для каждого типа пользователей.
