# Обработка данных

Датасет VK-LSVD создавался специально для проверки гипотез и соревнований, 
поэтому исходные данные не требуют сложной очистки или нормализации. 
Однако для приведения данных к виду, пригодному для обучения моделей, 
выполняется ряд преобразований **на лету** (без сохранения промежуточных 
результатов на диск, поскольку размер подвыборки позволяет пересчитывать 
данные при каждом запуске быстрее, чем читать их с диска).

## Единая разметка позитив/негатив

Все модели используют **единый механизм разметки** (`common/labels.py`), 
агрегирующий неявные и явные сигналы:

- **Позитивное действие** (`label = 1`): длительность просмотра 
  `timespent ≥ 5 секунд` ИЛИ наличие хотя бы одной позитивной реакции 
  (`like`, `share`, `bookmark`, `click_on_author`, `open_comments`).
- **Негативное действие** (`label = 0`): не является позитивным И 
  (`timespent < 5 секунд` ИЛИ явный `dislike`).

Применяется правило **«позитив побеждает»**: при наличии любого 
позитивного сигнала действие считается позитивным, даже если стоит 
`dislike`. Null-значения в полях реакций трактуются как `False`, 
null в `timespent` — как `0`. Строки, не попавшие ни в одну категорию, 
отбрасываются.

## Общие преобразования

Для всех моделей выполняются следующие шаги:

1. **Построение компактных индексов.** Исходные `user_id` и `item_id` 
   отображаются в плотные целочисленные индексы `0..N-1` (по отсортированным 
   ID для воспроизводимости).
2. **Восстановление хронологии.** Поскольку в датасете отсутствует колонка 
   `timestamp`, порядок взаимодействий определяется порядком строк в 
   parquet-файлах. Перед группировкой по `user_id` данные явно сортируются 
   по глобальному индексу строки.
3. **Построение множества `seen`.** Для каждого пользователя собирается 
   множество всех айтемов, с которыми он взаимодействовал в тренировочном 
   периоде (и позитивные, и негативные). Это множество используется для 
   исключения уже увиденного из кандидатов при инференсе и расчёте метрик.
4. **Построение валидационной выборки.** Из валидационной недели отбираются 
   только позитивные айтемы, которых нет в `seen` пользователя (иначе 
   предсказывать нечего).

## Модель-специфичные преобразования

- **MostPopular.** Подсчёт популярности каждого айтема как числа позитивных 
  взаимодействий в тренировочном периоде.
- **FPMC.** Построение триплетов `(user, last_item, next_item)` по 
  последовательным позитивным айтемам в истории пользователя.
- **LightGCN.** Построение двудольного графа «пользователь–ролик» по 
  позитивным рёбрам и вычисление симметрично нормализованной матрицы 
  смежности $\tilde{A} = D^{-1/2} A D^{-1/2}$.
- **SASRec.** Построение слайдинг-окон: для каждого позитивного айтема 
  целевой недели формируется сэмпл `(история за последние N недель, 
  целевой айтем, явные негативы)`.

## Negative sampling

Для обучения моделей с BPR-функцией потерь (FPMC, LightGCN, SASRec) 
используется единый механизм negative sampling (`common/negatives.py`):

- **Приоритет:** случайный айтем из явных негативов пользователя 
  (skip/dislike), если они есть.
- **Иначе:** случайный айтем из всего словаря.
- **Критично:** из кандидатов исключаются **все позитивные айтемы 
  пользователя** (а не только текущий `pos_item`), чтобы модель не 
  обучалась на «негативах», которые на самом деле являются позитивными.
