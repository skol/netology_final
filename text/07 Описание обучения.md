# Обучение моделей и валидация
Обучение всех персонализированных моделей проводится в едином пайплайне с жестким временным разделением данных (temporal
split) для предотвращения утечки данных из будущего (data leakage).

## Стратегия разделения данных

- **Тренировочный период:** недели 00 – 24. Все взаимодействия за этот период используются для построения
  пользовательских профилей, графов и последовательностей.
- **Валидационный/тестовый период:** неделя 25. Взаимодействия этой недели используются исключительно как ground truth 
  (целевые ответы) для оценки качества предсказаний.

## Функция потерь и оптимизация

Для моделей **FPMC**, **LightGCN** и **SASRec** используется функция потерь **BPR (Bayesian Personalized Ranking)**. В
отличие от попарной классификации (BCE), BPR оптимизирует непосредственно ранжирование, максимизируя разницу между
скором позитивного и негативного айтема для одного пользователя:
$$\mathcal{L}_{BPR}=-\sum_{(u,i,j)\in D} \ln \sigma(\hat{y}_{u,i} - \hat{y}_{u,j}) + \lambda \|\Theta\|^2$$
где:
- $u$ — пользователь,
- $i$ — позитивный айтем (из истории взаимодействий),
- $j$ — негативный айтем (семплированный),
- $\hat{y}_{u,i}$ и $\hat{y}_{u,j}$ — предсказанные скоры,
- $\sigma$ — сигмоида,
- $\Theta$ — параметры модели (для регуляризации).

Оптимизация проводится с использованием алгоритма **Adam** с базовой скоростью обучения $lr = 10^{-3}$. Модель
**MostPopular** является эвристической и не требует этапа градиентного обучения.

## Механизм Negative Sampling

Качество BPR-обучения критически зависит от корректности выбора негативных примеров. В проекте реализован единый строгий
механизм семплирования (common/negatives.py):

1. Приоритет явным негативам: если у пользователя есть история явных отказов (дизлайки, свайпы), негативный айтем
   выбирается случайно из этого множества.
2. Fallback на равномерное распределение: если явных негативов нет, айтем выбирается равномерно из всего словаря
   $\mathcal{I}$.
3. **Строгое исключение позитивов (Критично):** из пула кандидатов на роль негативного айтема **исключаются все айтемы, с
   которыми пользователь имел позитивные взаимодействия в тренировочном периоде**. Это предотвращает ситуацию, когда
   модель штрафуется за предсказание айтема, который пользователю на самом деле нравится.

## Процедура валидации и метрики

Оценка качества проводится на валидационной неделе для каждого пользователя индивидуально.

**Ключевое правило валидации:** перед ранжированием из множества всех возможных кандидатов $\mathcal{I}$ удаляются все
айтемы из множества $\mathbf{S_{u}}$ (все айтемы, с которыми пользователь взаимодействовал в тренировочном периоде, как
позитивно, так и негативно). Модель оценивается только по способности находить новые релевантные айтемы.

Для оценки используются стандартные метрики ранжирования (при $K=10$):
- **Recall@K:** доля целевых айтемов, попавших в топ-$K$ рекомендаций.
- **NDCG@K** **(Normalized Discounted Cumulative Gain):** учитывает не только факт попадания в топ-$K$, но и позицию
  айтема (выше позиция — выше вклад в метрику).
- **MRR (Mean Reciprocal Rank):** среднее значение величины, обратной рангу первого релевантного айтема.

## Построение гибридного ансамбля

После независимого обучения и валидации всех четырех моделей производится агрегация результатов для построения гибридной
системы.

Пользователи валидационной выборки разделяются на три группы на основе размера их тренировочной истории (количество всех
взаимодействий):
- **Cold**
- **Warm**
- **Hot**

Для каждой группы независимо вычисляются метрики (Recall@K, NDCG@K) по каждой из четырех моделей. Модель, показавшая
наилучший результат для конкретной группы, фиксируется как используемая для пользователей этой категории в
финальном инференсе.

_Примечание: автоматическое обновление границ исходя из обновления статистики не реализовано. Задача деплоя на prod не
рассматривалась, и реализация стратегии пересчета статистики и коррекции разбиения на группы остается в перспективных
планах._
